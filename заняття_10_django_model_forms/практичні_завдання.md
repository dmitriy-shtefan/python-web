# Практичні завдання

## Тема

Самостійні доробки до сценарію запису студента на курс.

## Завдання 1. Заборонити повторний запис на той самий курс

У view запису на курс додайте перевірку:

- поточний користувач уже має активний запис на вибраний курс;
- якщо запис існує, новий `Enrollment` не створюється;
- користувач бачить помилку біля поля `course`;
- після помилки форма залишається на сторінці `/enroll/`;
- після успішного запису користувача перенаправляє на `/my-courses/`.

Підказки:

- курс береться з `form.cleaned_data`;
- перевірка має враховувати `student=request.user`;
- можна скористатись методом .exists() на QuerySet який повертає True/False, залежно від кількості даних в QuerySet
- не забувайте про `is_active=True`.

## Завдання 2. Показувати пункти navbar тільки авторизованим користувачам

Оновіть navbar так, щоб анонімний користувач не бачив:

- `Мої курси`;
- `Запис на курс` або `Записатися на курс`.

Авторизований користувач має бачити ці посилання.

Перевірте вручну:

- відкрийте сайт без login;
- увійдіть як `student1`;
- вийдіть з акаунта;
- переконайтеся, що navbar змінюється після кожної дії.

## Завдання 3. Показати порожній стан у "Моїх курсах"

Оновіть сторінку `/my-courses/`:

- якщо записів немає, показати коротке повідомлення;
- якщо записи є, показати список назв курсів;
- не показувати записи інших користувачів;
- не показувати записи з `is_active=False`.

Підказка: queryset має фільтруватися по поточному користувачу.

## Завдання 4. Додати повідомлення після успішного запису

Після успішного запису покажіть користувачу повідомлення на сторінці `Мої курси`.

Вимоги:

- використайте Django messages;
- повідомлення має з'явитися один раз після redirect;
- текст має бути зрозумілим для студента, наприклад `Ви записалися на курс.`;
- повідомлення не має з'являтися після звичайного оновлення сторінки.

## Завдання 5. Перевірити сценарії двох студентів

Створіть або використайте тестових користувачів:

- `student1`;
- `student2`.

Перевірте сценарії:

1. `student1` записується на курс.
2. `student1` бачить цей курс у `/my-courses/`.
3. `student1` не може записатися на той самий курс повторно.
4. `student2` не бачить курсів `student1`.
5. `student2` може записатися на той самий курс від свого імені.

## Додаткове завдання

Зробіть список курсів у формі запису зручнішим:

- у label або тексті сторінки поясніть, що студент обирає курс для себе;
- додайте посилання з порожнього стану `/my-courses/` на сторінку запису;

## Перевірка

- anonymous не бачить у navbar `Мої курси` і `Запис на курс`;
- anonymous не може відкрити `/enroll/`;
- `student1` може записатися на курс;
- повторний запис `student1` на той самий курс показує помилку;
- `student1` бачить тільки свої активні записи;
- `student2` не бачить записи `student1`;
- після успішного `POST` відбувається redirect.

## Питання

1. Чому повторний запис треба перевіряти на рівні view або моделі, а не тільки в шаблоні?
2. Чому `student` не має бути полем у `EnrollmentForm`?
3. Який queryset захищає "Мої курси" від чужих записів?
4. Чому після успішного `POST` потрібен redirect?
