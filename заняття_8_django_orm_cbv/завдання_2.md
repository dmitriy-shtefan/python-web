# Завдання складність 3

## Мета

Додати другу model і перший реальний зв'язок `ForeignKey`, а потім показати пов'язані дані на сторінках сайту.

## Завдання

1. Переконайтеся, що вже працює:

- сторінка списку бере дані з БД;
- сторінка деталей відкривається через `pk`;
- посилання зі списку ведуть на правильні деталі;
- записи створені через admin.

2. Оберіть другу model для вашої предметної області.

Приклади:

- `Category` для `Product`;
- `Author` для `Article`;
- `Teacher` для `Course`;
- `Client` для `Order`;
- `Project` для `Task`;
- `Brand` для `Car`;
- `Doctor` для `Appointment`.

3. Створіть другу model з 2-4 осмисленими полями і `__str__`.

Орієнтир:

```python
class Category(models.Model):
    name = models.CharField(max_length=100)
    description = models.TextField(blank=True)

    def __str__(self):
        return self.name
```

4. Додайте `ForeignKey` в основну model.

Орієнтир:

```python
class Product(models.Model):
    category = models.ForeignKey(
        Category,
        on_delete=models.CASCADE,
        related_name="products",
    )
    title = models.CharField(max_length=200)
    description = models.TextField(blank=True)
    price = models.DecimalField(max_digits=8, decimal_places=2)

    def __str__(self):
        return self.title
```

5. Зробіть і застосуйте міграцію.

```bash
python manage.py makemigrations
python manage.py migrate
```

Якщо Django питає, що робити зі старими записами без значення для `ForeignKey`,
оберіть один із нормальних варіантів:

- тимчасово додайте `null=True, blank=True`, виконайте міграцію, заповніть значення в admin;
- або створіть default-об'єкт і використайте його для старих записів;
- або, якщо це навчальні тестові дані, видаліть старі записи й створіть нові після міграції.

Важливо: розуміти, чому старі записи не мають значення для нового обов'язкового зв'язку.

6. Зареєструйте другу model в admin.

Орієнтир:

```python
from django.contrib import admin
from .models import Category, Product


admin.site.register(Category)
admin.site.register(Product)
```

7. Через admin створіть:

8. Виведіть пов'язане поле на сторінці списку.

Орієнтир:

10. Додайте просту фільтрацію у view або виконайте її в shell.

Варіанти ORM-запитів:

```python
Product.objects.filter(category__name="Одяг")
Product.objects.filter(price__gte=1000)
Product.objects.filter(category=category)
Category.objects.get(name="Одяг").products.all()
```

11. Якщо залишився час, додайте окрему сторінку списку для другої model (якщо у вас такої немає).

Наприклад, список категорій:

```python
def category_list(request):
    categories = Category.objects.all()
    return render(request, "products/category_list.html", {"categories": categories})
```

У template можна показати назву категорії та кількість або список пов'язаних записів.

## Що здати

- `models.py` з двома models і `ForeignKey`;
- файл міграції, який додає другу model або зв'язок;
- `admin.py`;
- `views.py`;
- `urls.py`;
- template списку;
- template деталей;
- admin з обома models;
- сторінку, де видно поле пов'язаного об'єкта.

Усно пояснити:

- які дві сутності пов'язані між собою;
- чому це зв'язок "один до багатьох";
- що означає `on_delete=models.CASCADE`;
- навіщо потрібен `related_name`;
- який ORM-запит бере дані для списку;
- як у template працює звернення типу `{{ product.category.name }}`;
- яку проблему вирішує `ForeignKey` порівняно з дублюванням тексту.
