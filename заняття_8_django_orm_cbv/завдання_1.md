# Завдання складність 2

## Мета

Підключити основну model проєкту до реальних сторінок сайту через ORM і templates.

До кінця роботи має бути:

- основна model з кількома записами в admin;
- сторінка списку, яка бере дані з БД через ORM;
- template з циклом `{% for %}`;
- сторінка деталей одного запису через `pk`;
- посилання зі списку на детальну сторінку;
- нормальна 404-поведінка, якщо запис не знайдено;
- коротке пояснення шляху даних: DB -> ORM -> view -> template.

## Завдання

1. Перевірте, що у вас є основна model і 5-7 реалістичних записів у admin.

   Якщо записів мало, додайте їх через admin перед роботою зі сторінками.

2. У `views.py` імпортуйте свою model.

Орієнтир:

```python
from django.shortcuts import render
from .models import Product
```

3. Створіть або переробіть view для сторінки списку.

Дані мають братися з бази через ORM, а не з Python-списку.

Орієнтир:

```python
def product_list(request):
    products = Product.objects.all()
    return render(request, "products/product_list.html", {"products": products})
```

4. У template списку виведіть записи через цикл.

Орієнтир:

```django
{% for product in products %}
    <h2>{{ product.title }}</h2>
    <p>{{ product.description }}</p>
{% empty %}
    <p>Поки немає записів.</p>
{% endfor %}
```

5. Додайте URL для списку, якщо його ще немає.

Орієнтир:

```python
path("products/", views.product_list, name="product_list")
```

6. Створіть view для сторінки деталей через `pk`.

Орієнтир:

```python
from django.shortcuts import get_object_or_404, render
from .models import Product


def product_detail(request, pk):
    product = get_object_or_404(Product, pk=pk)
    return render(request, "products/product_detail.html", {"product": product})
```

7. Додайте URL для сторінки деталей.

Орієнтир:

```python
path("products/<int:pk>/", views.product_detail, name="product_detail")
```

8. У template списку додайте посилання на сторінку деталей.

Орієнтир:

```django
<a href="{% url 'product_detail' product.pk %}">{{ product.title }}</a>
```

9. Створіть template деталей і виведіть 4-6 полів одного запису.

Орієнтир:

```django
<h1>{{ product.title }}</h1>
<p>{{ product.description }}</p>
<p>Ціна: {{ product.price }}</p>
<p>Доступний: {{ product.is_available }}</p>
```

10. Перевірте вручну:

- сторінка списку відкривається;
- на ній видно записи з admin;
- кожне посилання веде на правильну сторінку деталей;
- неіснуючий `pk` не ламає сайт, а дає 404.

## Що здати

Показати викладачу:

- `models.py`;
- `views.py`;
- `urls.py`;
- template списку;
- template деталей;
- admin зі записами;
- сторінку списку в браузері;
- одну сторінку деталей у браузері.

Усно пояснити:

- який ORM-запит використовується для списку;
- як `pk` потрапляє з URL у view;
- чому використано `get_object_or_404`;
- які дані передаються в context;
- чому дані більше не треба дублювати у Python-списку.
